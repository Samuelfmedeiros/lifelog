## Terça-feira, um tracker que não envelhece

O post de hoje não é sobre um bug. É sobre o que sobra quando três dias de manutenção passam pelo mesmo repositório — e o que cada mudança deixou pra trás.

Começa na terça (10/09). O portfólio usa um analytics self-hosted, e a integração era uma linha no layout: um `<script>` apontando pro tracker. Funcionava. Exceto quando não funcionava — eu tinha atualizado o script lá no servidor e o navegador dos visitantes continuava rodando a versão antiga, às vezes por dias.

O diagnóstico foi uma linha de header:

```http
cache-control: public, max-age=31536000, immutable
```

Um ano de cache. Imutável. No **script** de analytics.

Immutable é a promessa que você dá ao navegador: "este URL nunca vai mudar de conteúdo". É perfeito pra bundles com hash no nome — `/_next/static/chunk-abc123.js` muda de nome quando muda de conteúdo, então pode congelar o cache sem medo. O problema é quando a mesma promessa cobre um arquivo que **muda sem trocar de nome**. O navegador faz o oposto do que você quer: quando você conserta o tracker, ele educadamente ignora a correção até o cache expirar.

A correção foi pequena de escrever e conceitual de entender:

```tsx
<script src="/analytics/script.js?v=2" />
```

Query string no URL. O `?v=2` não muda nada pro servidor — mas muda tudo pro cache. URL novo, entrada de cache nova. É o mesmo truque que eu já tinha aprendido na pele com as capas do blog: **trocar conteúdo no mesmo URL é invisível pra quem já carregou**. Asset imutável + conteúdo novo = correção que só você vê.

## Madrugada de sexta, o revert que veio de fora

Sexta-feira (05/09), 03:55. Um commit chega no repositório — de outra máquina. "Revert Merge PR #72": o resume tailor, a ferramenta que analisa um currículo contra uma vaga com IA, tinha sido removido inteiro da árvore. Route, componentes, lib — fora.

Na sexta mesma eu fiz o merge daquele revert, consertei um copyright duplicado no rodapé que apareceu no caminho, e o dia fechou com três commits. O projeto seguiu sem o V5. Nenhum drama: o revert existia porque a feature tinha sido desativada por decisão anterior, e o merge só consolidou o estado.

Mas toda feature revertida deixa um rastro: os testes que cobriam ela, os padrões que ela estabeleceu, a pergunta "e se a gente trouxer de volta?". O revert não responde — só adia.

## A volta, agora com um LLM no meio do caminho

Segunda (09/09) foi dia de integração massiva de dependabot — nove PRs de dev-dependencies, do vercel 58.9 pro 59.11, vitest 4 pro 5, framer-motion, mercadopago. O tipo de dia que não vira post porque "atualizou dependências" não tem conflito, tem só disciplina.

E então ontem (10/09, tarde), o V5 voltou. Commit único, mensagem sincera:

```bash
$ git log -1 --format=%B
feat(resume-tailor): V5 reintroduzido com cadeia LLM no 9router
(via Arachne) e falha alta

- Rota usa /api/llm/chat do Arachne (9router por tras) com fallback
  direto em RESUME_LLM_URL para dev; fim da corrida de modelos free
  hardcoded.
- LLM indisponivel agora responde 502 (antes: PDF placeholder com
  HTTP 200).
- Guard anti-eco do template do prompt (looksLikePromptEcho) + testes.
- Reintroduz os arquivos do V5 removidos pelo revert 4dd1a99.
```

Três decisões de design valem o registro.

**Primeira: a cadeia de LLM saiu do código do portfólio.** A versão anterior mantinha uma lista de modelos gratuitos com fallback em cascula — cada um podia sumir, e o fallback virava lista de Natal. Agora a rota fala com o gateway de LLM que já roda no meu ecossistema (que por sua vez orquestra provedores, rate limit e rotação), com um fallback de URL direto só pro ambiente local. O portfólio não sabe mais quais modelos existem — e é assim que deve ser.

**Segunda: falhar alto.** A versão antiga tinha um comportamento que eu considero crime hoje: quando o LLM não respondia, ela gerava um PDF placeholder e respondia HTTP 200. O usuário recebia um documento vazio e achou que era aquilo. Agora: 502. Erro explícito, sem disfarce.

**Terceira: o guard anti-eco.** LLM às vezes "responde" repetindo o próprio prompt. Detectável — o output parece com o template, não com uma análise. Um detector simples (com testes) rejeita esse eco antes de virar PDF.

O revert e a reintrodução não se cancelam: o primeiro limpou, o segundo voltou com arquitetura diferente. Se o V5 tivesse voltado igualzinho, o revert não teria servido pra nada.

## O que sobra

Terça fechou com um commit só — o cache-bust do tracker. Dia leve, do tipo que a rotina de fim de dia documenta e ninguém mais menciona. Mas os três dias contam a mesma história de lados diferentes:

| Dia | Mudança | O rastro |
|-----|---------|----------|
| 05/09 | Revert do V5 + fix footer | Copyright único, pergunta em aberto |
| 09/09 | 9 PRs dependabot | Deps dev atualizadas, zero drama |
| 10/09 | Cache-bust `?v=2` | Tracker atualiza quando deveria |
| 10/09 | V5 reintroduzido | LLM atrás de gateway, falha honesta |

Cache imutável ensinou: **a imutabilidade é uma promessa sobre o conteúdo, e só vale quando o nome carrega essa promessa junto**. O revert ensinou: desfazer é mais barato que conviver com o errado. E a reintrodução ensinou: quando uma feature volta, ela deve voltar melhor — se for idêntica, o intervalo não ensinou nada.

O próximo post do blog que citar um asset novo vai levar `?v=` no URL desde o commit. Aprendi na dor duas vezes — capa e tracker — pra nunca mais esquecer uma.
