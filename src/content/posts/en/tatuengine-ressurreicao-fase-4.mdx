## The day nothing would compile

There's something every low-level tool developer learns early: the operating system is not your quiet friend. One day it decides to update itself in the middle of the night, and the next morning the project that worked yesterday simply refuses to be born.

That's exactly what happened to TatuEngine. The WSL distro upgraded — new libc, new compiler, everything in place — and the build that was 100% the day before collapsed. It wasn't a change in my code. It was the ground beneath it that moved.

## The diagnosis

The first error that appeared was the classic compatibility one: the new compiler rejected the CUDA toolchain I was using. Combinations that used to be stable became forbidden overnight, and the whole project stopped compiling because of a version war between three tools that aren't even mine.

The diagnosis pattern was the usual one for TatuEngine:

1. **Isolate** — run a clean build and read the FIRST error, not the last one. The first one tells the real story.
2. **Identify the conflict** — it was a triad: new libc, new compiler, and CUDA with its own compatibility rules. The right combination existed, but it wasn't the one installed.
3. **Fix the ground** — pin the toolchain to a combination known to be stable. Sometimes "updating" isn't the answer; it's choosing the version that talks to the others.
4. **Silence the rest** — after the toolchain, the compiler started complaining about a modern C++ detail: six math functions needed to be marked as non-throwing. A thin patch, three lines in each one, and the noise was gone.

It wasn't glamorous. It was precision surgery on functions nobody looks at, in the file nobody opens, because the new compiler decided to get stricter.

## Green came back

After the fix, the build went back to 100%. And the proof that nothing had broken along the way was `ctest`: **32/32 tests passing**, in 41 seconds.

There's a specific moment in this kind of morning — when the last suite lights up green and you check that the test count is exactly the same as yesterday. It's the confirmation that the fix didn't hide anything, it just unlocked what the update had locked.

## Phase 4 was authorized

With the build alive again, the next step was clear: get back to the plan. TatuEngine has an architect who guides the training phases, and I had just reached the end of Phase 3. I went there, told the story (the build scare, the fix, the 32 green tests) and asked for ignition.

The answer came: **Phase 4 — Resurrection, Hybrid Option C, authorized**.

The name couldn't be more fitting. Phase 4's plan is literally to resume training from the champion warmup checkpoint — the best version Phase 3 left behind — and give it a second wind:

- **Clean load** — start from the champion checkpoint, without dragging junk from intermediate states.
- **Firmer optimizer** — a fused variant of AdamW, with parameter groups receiving different learning rates (some faster, others slow).
- **Hybrid loop** — alternate the two training phases in a single run, instead of one after the other.
- **Separate telemetry** — track the two losses independently after the initial warmup, so I know exactly which phase is evolving.

And there's a decision on my desk: the relative weight between the two losses in training — keep a fixed ratio from start to finish, or let it decay over time, ending quite differently from how it began. It's the kind of choice that changes the final model's behavior, and it's still open.

## Lessons learned

- **A system update is a risk event, not routine.** Code that compiles today may not compile tomorrow without you touching anything. Pinning the toolchain (or documenting it rigorously) is worth the cost.
- **The first build error is the signal, not the problem.** Reading the top of the stack saved hours of chasing symptoms.
- **"Updating" isn't always the answer.** Sometimes the fix is pinning a combination of versions known to talk to each other — even if they're not the newest.
- **An equal test count is silent proof.** When 32/32 come back green with the same count, the fix is honest.

## What's next

The Resurrection has begun. With the build stable and Phase 4 authorized, the next step is building the hybrid run — loading the champion checkpoint, configuring the optimizer with the parameter groups, and letting training run with both losses measured side by side. The relative-weight decision between them is mine, and it sets the pace for everything.

The engine that almost didn't start today is the same one that will spend weeks burning GPU. The irony is perfect.
