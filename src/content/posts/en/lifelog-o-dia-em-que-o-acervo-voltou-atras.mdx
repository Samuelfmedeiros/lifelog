## The paragraph I should never have written

There was a post online explaining the architecture of a compression engine. The text was good: it told the decision to ternarize weights, showed the memory cost before and after, owned what had gone wrong. At the end, after all the learning, there was a paragraph offering the source code for a price and a setup service for another.

Writing about what you build is the whole point of this blog. Selling inside the post, using the post itself as bait, is a different thing. The paragraph came out fast — one commit, one line, two deletions (`78a5d5c`) — and on the same day the entire post left the archive (`ba64e93`). But how easy the fix was hid the size of the problem: if one post had this, how many others did?

## Four sweeps in four days

The answer came in pieces, and no single sweep gave the full picture.

The first one (`3236d0f`) went after the numbers. Twelve published posts cited internal metrics from one of the projects — compression factor, structure size, memory footprint, measured GPU speedup. Individually each number looked like an innocent technical detail. Together they formed the recipe: any reader with enough experience could reconstruct the whole approach without ever opening the repository. Thirteen files were touched across Portuguese and English, 91 lines coming in and 75 going out.

The lesson arrived an hour later. The sweep had cleaned twelve posts and declared the archive cured. It was not: two files still carried residual recipe, and the next commit (`9051fdf`) removed 142 lines and added 24. I had declared the problem solved before running the check again — which is exactly the same mistake as assuming that absence of proof is proof of success.

The third sweep (`8f41488`) was humiliating for a different reason: it did not leak technology, it leaked money. Two posts from another project showed real revenue, month by month, in cash — a weekly table with value per week and another one with walks, withdrawals, fees and chargebacks from two months, with percentage change. The text got better once the numbers were gone: where there was an exact amount came "went up", where there was a net figure falling 9% came "fell despite the raw growth". The story lost nothing. It lost the wrong reader, which is the only one who cares about the exact figure.

The fourth one (`b3fdaf3`) fixed a broken pair: the English version of one post had never been versioned, so the recipe cleanup had only hit the Portuguese file. The fix created the missing pair and cleaned the rest in the same commit — because fixing one language and leaving the other dirty is half a fix.

## The gate born alongside it

Editing fourteen posts by hand is a patch. The generator would repeat the pattern on the next post, and nobody would notice until the next leak. So the sweep became a gate: a step in the pipeline that opens the body of every article and looks for the category, never the value.

```python
RECIPE = [
    ("codec-interno",        re.compile(...)),   # internal algorithm name
    ("fator-compressao",     re.compile(...)),   # measured compression ratio
    ("tamanho-estrutura",    re.compile(...)),   # on-disk structure size
    ("footprint-brut",       re.compile(...)),   # memory required to run
    ("footprint-intermediario", re.compile(...)),# intermediate pipeline stage
    ("bloco",                re.compile(...)),   # block granularity
    ("speedup",              re.compile(...)),   # measured GPU gain
    ("mse",                  re.compile(...)),   # validation error
]

for label, rx in RECIPE:
    if rx.search(body):
        errors.append(("E4", rel, f"receita TatuEngine no corpo ({label})"))
```

Each pair is a label and a pattern. The label shows up in the error, so the message says *what* leaked without reprinting *how much* — the gate reports the category and never prints the forbidden number into the log. And the list lives in the gate, not in the post: adjusting the recipe means changing one line in the checker, not hunting text scattered across the archive.

The part that only became clear at the end: the gate also reads hidden posts. A hidden post is not a private post — it is a post waiting for release, and what is written today is what goes up tomorrow. Leaking in the hidden pool only chooses the date of the leak.

## What changed

The archive now holds 456 articles and the gate answers zero errors. None of them was rewritten to hide the story: the narratives are still whole, with decisions, trade-offs and the real numbers where the number is mine — commits, lines removed, files touched, test coverage. What came out was what was never mine to publish: implementation recipe unrelated to the narrative, and real money from the operation.

The rule that survived applies to anything published: **unpublishing is also a commit, and it needs verification**. The first sweep proved that a well-done fix still leaves residue, and that the residue only shows up when someone runs the check again on top of what was just fixed — not when someone decides it is done.

## Next step

The gate already covers absolute paths, operation blocks at the end, the hidden-post footer and proprietary recipe. One category is missing: commercial terms and prices cited in any post, which was exactly the defect of the original paragraph and today is only caught by memory. That is the next rule to enter the list — and, like this one, it will be born first as a sweep across the entire archive, to see how many existing posts still carry what should never have been there.
