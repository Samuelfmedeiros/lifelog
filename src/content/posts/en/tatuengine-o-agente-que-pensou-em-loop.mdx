The TatuEngine's autopoietic agent had existed on paper for months. The architecture was drawn, the model was trained, the machine was there. Only one thing was missing: the cycle had never run to the end.

The cycle is simple in intent — think, evaluate, decide, observe the result, repeat until the agent declares it is done. The function that orchestrates it calls the decider at every step. The problem was that the decider carried three chained defects, each one alone enough to stall everything. And, like most integration defects, none of them made any noise.

## Three ways to stall without a warning

The first was a contract problem. One stage called the next with a set of arguments the implementation no longer accepted. The call threw, the exception was caught by a broad handler and dropped. The state the next decision read stayed at its initial value — always below the threshold that declares completion, and nobody knew why.

The second was accumulated state. The component that reads the model output kept a buffer between calls. On every iteration the previous answer was emitted again: the agent thought the same thing twice while the transcript grew without moving a step forward. The fix is to reset the reader before each read, guaranteeing one answer per cycle.

```python
def loop(step):
    state = State.initial()
    while not state.done:
        reader.reset()                     # one answer per iteration
        answer = reader.read(model.think(state))
        state = step(state, answer)
    return state
```

The third was a path problem. A native component was not where the process looked for it. The file existed in the repository, the tests passed, but loading pointed at another directory. Nothing came up — and the symptom looked like a missing resource, not a configuration error. Three lines of path resolution fix it; without them, nothing loaded.

With all three fixed, the cycle closes when the evaluator is healthy and stops at the max-cycles breaker when it is adrift. The proof runs with simulated model and evaluator, no GPU — which also means it measures the integration, not the quality of the answers.

## The core was broken too, and out of the path

Below the agent there was a more basic defect. A decision method used a variable that only existed in the evaluation scope; on the tool-execution path that raised on the first line. And a model step function had its parameter renamed in one place while the body still referenced the old name.

The audit that followed did not trust what compiles: it read the import graph. A good part of the core — precisely the heaviest modules — was not imported by anything in production. Code written, tested, versioned and outside the execution path. That kind of finding does not show up in a unit test; it shows up when someone draws who calls whom.

## Teaching the model not to drown in its own mistakes

In parallel with the agent, training gained a change in exposure. The idea is simple: on a second pass, the model generates the first steps of the answer with its own guess and the loss is measured against the golden label. With the switch off, the old recipe is reproduced bit for bit — nothing changes for whoever did not ask for it.

The second problem there was not algorithmic, it was scheduling. The horizon of the learning-rate decay was tied to the total training step budget. Raising the budget also raised the stretch with high learning rate; a recent run degraded and aborted because of it. The fix decouples the two: decay ends where it was defined and the rest stays at the floor. Without the parameter, the behaviour is identical to before.

## Comparing two runs without fooling yourself

Validating whether one run beat another required comparing checkpoints — and that surfaced another method problem. Each checkpoint stores only the trainable deltas, not the whole model. Comparing two checkpoints applied over different models, or measured on different holdouts, proves nothing but noise.

The comparator rebuilds the trunk once, applies the first checkpoint, measures, zeroes the deltas and applies the second. Both runs go through the same model and the same holdout, with the pure trunk as baseline.

## What changes

The agent stopped being architecture on paper. The cycle closes, the decider decides, the core no longer throws on the first call, training no longer loses its shape when the budget grows, and validation compares runs fairly.

The pattern tying the three integration defects together is always the same: all of them failed in silence. A swallowed exception, a module outside the execution path, a schedule that only shows its error when the budget changes. None of them breaks the build. All of them produce a system that looks alive without ever being exercised end to end.

The next step is wiring the cycle to a real interface and measuring whether it closes simple tasks without human intervention. The architecture is ready; the proof of use is still missing.
