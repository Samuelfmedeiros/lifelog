## Tuesday, a tracker that never ages

Today's post is not about a bug. It's about what's left when three days of maintenance pass through the same repository — and what each change left behind.

It starts on Tuesday (09/10). The portfolio uses self-hosted analytics, and the integration was a single line in the layout: a `<script>` tag pointing to the tracker. It worked. Except when it didn't — I had updated the script on the server and visitors' browsers kept running the old version, sometimes for days.

The diagnosis fit in one header line:

```http
cache-control: public, max-age=31536000, immutable
```

One year of caching. Immutable. On the **analytics script**.

Immutable is the promise you make to the browser: "this URL's content will never change". It's perfect for bundles with a hash in the name — `/_next/static/chunk-abc123.js` gets a new name when its content changes, so you can freeze its cache without fear. The problem shows up when the same promise covers a file that **changes without changing its name**. The browser does the exact opposite of what you want: when you fix the tracker, it politely ignores the fix until the cache expires.

The fix was small to write and conceptual to understand:

```tsx
<script src="/analytics/script.js?v=2" />
```

Query string on the URL. The `?v=2` changes nothing for the server — but it changes everything for the cache. New URL, new cache entry. It's the same trick I had already learned the hard way with this blog's cover images: **replacing content at the same URL is invisible to anyone who already loaded it**. Immutable asset + new content = a fix only you can see.

## Friday before dawn, the revert that came from outside

Friday (09/05), 03:55 AM. A commit lands in the repository — from another machine. "Revert Merge PR #72": the resume tailor, the tool that analyzes a résumé against a job opening with AI, had been removed from the tree entirely. Route, components, lib — gone.

That same Friday I merged the revert, fixed a duplicated copyright in the footer that showed up along the way, and the day closed with three commits. The project moved on without V5. No drama: the revert existed because the feature had been deactivated by an earlier decision, and the merge just consolidated that state.

But every reverted feature leaves a trail: the tests that covered it, the patterns it established, the question "what if we bring it back?". The revert doesn't answer — it only postpones.

## The return, now with an LLM in the middle of the path

Monday (09/09) was a dependabot integration day — nine dev-dependency PRs, from vercel 58.9 to 59.11, vitest 4 to 5, framer-motion, mercadopago. The kind of day that doesn't become a post because "updated dependencies" has no conflict, only discipline.

And then yesterday (09/10, late afternoon), V5 came back. Single commit, honest message:

```bash
$ git log -1 --format=%B
feat(resume-tailor): V5 reintroduced with LLM chain on the 9router
(via Arachne) and fail-loud behavior

- Route now uses the Arachne /api/llm/chat (9router behind it) with a
  direct RESUME_LLM_URL fallback for dev; end of the hardcoded free
  model race.
- Unavailable LLM now responds 502 (before: placeholder PDF with
  HTTP 200).
- Anti-echo guard for the prompt template (looksLikePromptEcho) +
  tests.
- Reintroduces the V5 files removed by revert 4dd1a99.
```

Three design decisions are worth recording.

**First: the LLM chain left the portfolio's code.** The previous version kept a list of free models with cascading fallbacks — each one could vanish, and the fallback list turned into a holiday wish list. Now the route talks to the LLM gateway that already runs in my ecosystem (which in turn orchestrates providers, rate limits and rotation), with a direct URL fallback only for the local environment. The portfolio no longer knows which models exist — and that's how it should be.

**Second: fail loud.** The old version had a behavior I now consider a crime: when the LLM didn't respond, it generated a placeholder PDF and answered HTTP 200. The user got an empty document and thought that was it. Now: 502. Explicit error, no disguise.

**Third: the anti-echo guard.** LLMs sometimes "answer" by repeating the prompt itself. Detectable — the output looks like the template, not like an analysis. A simple detector (with tests) rejects that echo before it becomes a PDF.

The revert and the reintroduction don't cancel each other out: the first one cleaned up, the second came back with a different architecture. If V5 had returned exactly the same, the revert would have been pointless.

## What remains

Tuesday closed with a single commit — the tracker's cache-bust. A light day, the kind the end-of-day routine documents and nobody mentions again. But the three days tell the same story from different angles:

| Day | Change | The trail |
|-----|--------|-----------|
| 09/05 | V5 revert + footer fix | Single copyright, open question |
| 09/09 | 9 dependabot PRs | Dev deps updated, zero drama |
| 09/10 | Cache-bust `?v=2` | Tracker updates when it should |
| 09/10 | V5 reintroduced | LLM behind a gateway, honest failure |

Immutable caching taught: **immutability is a promise about content, and it only holds when the name carries that promise too**. The revert taught: undoing is cheaper than living with the wrong thing. And the reintroduction taught: when a feature comes back, it should come back better — if it returns identical, the interval taught nothing.

The next blog post that cites a new asset will ship `?v=` in the URL from the very commit. I learned it the painful way twice — cover and tracker — so I never forget it again.
