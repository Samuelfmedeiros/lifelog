Building isolated projects is easy. Connecting them into a self-reinforcing ecosystem — that's the real challenge.

July was ending and I had 5 projects in production, each with its own stack, its own deploy, its own credentials. Capivara on WSL with PostgreSQL, Dogwalk on Cloudflare Pages, Hermes with a multi-platform gateway, Arachne with MCP, Portfolio on Vercel.

Each worked fine alone. But together? It was an archipelago — separate islands separated by different credentials, conflicting ports, manual deploys.

This week, three things changed.

## Capivara becomes a real PWA

Capivara has always been my personal hub — financial dashboard, health checks, telemetry. But it was just a website. You opened the browser, it worked, that's it.

The first big change was **full PWA offline support** with push notifications. Service worker caching files, manifest with icons, and push notifications via VAPID keys firing directly from the FastAPI backend.

```python
# Capivara — push notification via WebPush
from pywebpush import webpush, WebPushException

def send_push(subscription: dict, title: str, body: str):
    payload = json.dumps({
        "title": title,
        "body": body,
        "icon": "/icon-192.png",
        "badge": "/badge-72.png",
    })
    try:
        webpush(
            subscription_info=subscription,
            data=payload,
            vapid_private_key=VAPID_PRIVATE,
            vapid_claims={"sub": "mailto:admin@seu.pet"}
        )
    except WebPushException as ex:
        if ex.response and ex.response.status_code == 410:
            # subscription expired — remove from DB
            delete_subscription(subscription)
```

With this, the Capivara dashboard now:
- Notifies when a health check fails (even with browser closed)
- Works offline — daily financial data cached
- Exports CSV with one click (dashboard → spreadsheet)

The migration from `husky` to `lefthook` came along — git hooks that work on WSL without broken `PATH`. It sounds like a detail, but every WSL dev knows how husky breaks on Windows.

## Hermes: computer use that doesn't steal your cursor

Hermes always had computer use, but it was unstable — clicks that didn't land, types that lost context, broken permission in the gateway. The update to `cua-driver 0.10` with aligned permission modes fixed it:

- **Desktop control** routes input to the right app without stealing focus
- **Full-duplex voice barge-in** — I can interrupt Hermes mid-generation
- **Cron scrub** — all GitHub auth calls fixed to not leak tokens in logs

The real gain? I can delegate UI tasks to Hermes in the background while I keep working. It opens VSCode, clicks, types — and my cursor never moves.

## Dogwalk: unified Cloudflare auth

Dogwalk had an annoying problem: it used `CLOUDFLARE_API_KEY` in some scripts and `CLOUDFLARE_API_TOKEN` in others. When one expired, the deploy would fail silently.

The migration was simple in code, tedious in tracking:

```bash
# Before: 3 different ways to authenticate with Cloudflare
# 1. Old script: API_KEY via X-Auth-Key header
# 2. New deploy: API_TOKEN via Authorization: Bearer header
# 3. Wrangler: ~/.wrangler/config/default.toml

# After: ONE way — API_TOKEN everywhere
# And CLOUDFLARE_EMAIL only where API_KEY is still required
```

Seven commits just of auth cleanup. But since then, zero deploy failures from credentials.

## What's left

The ecosystem isn't "done" — it never will be. But the islands are starting to become bridges:

1. **Capivara** → push notifies when a server goes down
2. **Hermes** → reliable computer use to manage everything
3. **Dogwalk** → deploy without broken credentials
4. **Arachne** → MCP connectors integrated
5. **Portfolio** → CI/CD with automatic health check

Each piece still works alone. But together, they're starting to look like a system.
