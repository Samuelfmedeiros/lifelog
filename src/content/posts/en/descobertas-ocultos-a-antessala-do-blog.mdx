## Before: releasing a post was a ritual

The blog's rhythm changed over the last few months. The pipeline generates three posts a day, and each one is born hidden — the frontmatter carries `hidden: true`, so the post stays out of the feed, the RSS, everywhere. It exists only for me, waiting on a decision: publish, edit, or throw away.

The problem is that "waiting on a decision" carried an absurd cost. Releasing a post looked like this:

```bash
sed -i 's/hidden: true/hidden: false/' src/content/posts/my-post.mdx
sed -i 's/hidden: true/hidden: false/' src/content/posts/en/my-post.mdx
pnpm build
git add src/content/posts/my-post.mdx src/content/posts/en/my-post.mdx
git commit -m "release(post): my-post"
git push
# ... and hope the CI deploys
```

Six steps per language, plus build, plus commit, plus push. On a day when I released three posts, that was a fifteen-minute ritual of pasting commands. Worse: when I was on my phone — where I read 90% of my notifications — the temptation was always to postpone.

The question that kept nagging me: why does a *content* decision depend on a terminal?

## The format Vercel doesn't understand

The first attempt was the obvious one: the hidden post is already on the site after the build, right? Just hit the URL directly. Wrong — and the reason teaches how serverless deploys actually work.

The post page is static: the `hidden` filter runs at build time. If hidden posts don't generate a route, then `https://blog/post/slug/` doesn't exist at all. If they do generate one, they're only hidden from the index — anyone with the link gets in. Privacy by convention, which is the worst kind of privacy.

So the path had to be different: a dynamic, serverless page that lists hidden posts *from the build* and only shows them to whoever holds the password. The next problem showed up on the first line of code:

```javascript
// what I wrote first — works locally, breaks on deploy
import { readdirSync } from 'fs'
const dir = path.resolve(__dirname, '../src/content/posts')
```

It worked under `pnpm dev`. It worked under a local `pnpm build`. On Vercel: empty list, every time.

The cause is subtle to the point of pain. On a serverless deploy, the route code gets *bundled* — packed into a different directory, far from the repository tree. The `__dirname` that pointed to `src/content/posts` on my laptop pointed to a chunks folder on Vercel that will never contain an `.mdx`. And the silent `catch` I had added "for robustness" swallowed the error and returned an empty list — the worst kind of failure: the one that looks like missing data.

## The fix that simplifies everything

The solution was to stop asking the server to read the repository at runtime and do the work at the right moment — during the build:

```javascript
// scripts/gen-ocultos.mjs — runs BEFORE astro build
// 1. scans src/content/posts/ with gray-matter (parses only the frontmatter)
// 2. stores slug, title, date and project for anything with hidden: true
// 3. writes api/ocultos-data.mjs: export default [ ...posts ]
```

The serverless route stops touching the filesystem and becomes a plain import. The hidden data travels *inside* the bundle, generated by the machine with full context: the build machine. It's the SSG principle taken to its conclusion — if the data is known at build time, there is no justification for rediscovering it at runtime.

And the hidden posts themselves? With today's pipeline, none of them generate a public route. The `/hidden` page lists what exists awaiting a decision, and releasing is still a commit — but a one-click one.

## The antechamber

The final result is a page that exists only for me: password at the entrance, a list of posts awaiting a decision, and a release button per post. I open the link on my phone, see what the pipeline produced that day, and decide. What was a terminal ritual became two taps.

```bash
# the whole flow, from inside the page
POST /api/release { slug }   # flips hidden on both languages, commits and pushes
```

And the detail I like most: the hidden page doesn't leak. It's not in the sitemap, nothing links to it, and the password is checked on the server — it's not client-side JavaScript hiding content. Anyone arriving without credentials sees exactly what they'd see at any nonexistent route.

## Lessons

- **`__dirname` in serverless is a gamble.** The deploy bundle doesn't preserve the repository tree. If the data exists at build time, freeze it at build time — generate a module and import it.
- **A silent `catch` turns a bug into a mystery.** The empty list looked like "no hidden posts" when it was really "the readdir blew up". If a failure should be handled, handle it; if it shouldn't, let it be loud.
- **Frontmatter is an author's convention, not a runtime contract.** Vercel doesn't know what `hidden: true` means — only my build does. Every piece of content semantics must become a build artifact to survive a deploy.
- **Content decisions deserve their own UI.** Terminals are great for automating, terrible for deciding. A 60-line page beats a ruler of commands in your shell history.

The next step is already on paper: a "redo" button on the same page, pulling the rejection reason from the GitHub issue and feeding it back to the pipeline. The antechamber is ready — all that's missing is the complaint desk.
