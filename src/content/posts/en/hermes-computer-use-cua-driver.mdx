Hermes always had computer use. From the start, one of the most ambitious tools for the agent: controlling the mouse and keyboard like a human would.

In practice, it was a gamble. It clicked the wrong spot, the type lost context, the gateway permission broke. It worked sometimes — enough to show potential, not enough to trust.

## Three problems, one system

Hermes' computer use is a three-layer sandwich: the gateway (receives the command), cua-driver (executes on the OS), and the agent (decides what to do). Each layer had its own problem.

### 1. Permission modes misaligned

cua-driver 0.10 introduced a permission mode system: `standard`, `explicit`, `yolo` — each with a different restriction level for clicking, typing, screen capture. The problem was that Hermes' gateway used a different session-key namespace, so when the agent said "standard mode", the driver received "none mode" and blocked everything.

```
Gateway saves session-key as:
  user:default:session:abc123

cua-driver 0.10 expects:
  user::session:abc123

They never match → permission denied → click never happens
```

Commit `871404095` fixed it: align the session-key namespace between gateway and driver.

### 2. Desktop control without stealing focus

This was the most frustrating one. When Hermes clicked something, the mouse focus jumped to the target — I lost what I was doing. Commit `94d1dff50` introduced desktop control routing: the driver now routes input to the right app without bringing the window forward.

```typescript
// Before: clicking VSCode brought it to the foreground
computer_use.click({ element: 14 })
// → VSCode gains focus, your cursor disappears

// After: the click reaches VSCode, but your cursor never moves
computer_use.click({ element: 14 }, { delivery_mode: 'background' })
// → VSCode receives the click, you keep working
```

The secret is `delivery_mode: 'background'` — the input reaches the target process, but the OS doesn't swap focus. It sounds like magic, but it's just using the correct accessibility APIs on Windows/Linux.

### 3. Full-duplex voice barge-in

This was a bonus that came along: `e0233f8fc` — full-duplex voice barge-in. Before, if Hermes was generating a response and I said "stop", it would finish talking first. Now audio capture is full-duplex: it listens while it speaks.

In practice: "Hermes, open VSCode in the Dogwalk folder" → it starts replying "Sure, I'll open..." → "No wait, the Arachne folder instead" → it interrupts and corrects the path.

It sounds like a detail, but full-duplex changes the feel of a conversation. From turn-taking (each one waits their turn) to natural interruption (like two people talking).

## The real gain

After these three fixes, computer use went from "works sometimes" to "reliable enough to delegate."

Today I do:

```
"Hermes, open the last Playwright report for Dogwalk"
→ It opens VSCode, navigates to the project, opens the HTML report, takes a screenshot
→ All in the background — my cursor never moves

"Hermes, click 'Create Pull Request'"
→ It goes to GitHub, fills the form, submits the PR
→ I keep coding
```

Each individual fix seems small. A namespace, a delivery_mode, a full-duplex. Together they turned an experimental tool into something I use every day without thinking.
